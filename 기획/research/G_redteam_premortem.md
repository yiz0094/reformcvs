## 0. 조사 범위와 한계 (반드시 먼저 읽을 것)

### 0.1 검색 제약 고지
- 이 세션에서는 웹 검색(WebSearch) 호출 한도가 다른 에이전트와 공유되어 **이미 소진된 상태**였고, 검색을 한 번도 수행하지 못했다. 대신 **알려진 1차 출처 URL을 직접 열어(WebFetch)** 확인 가능한 사실만 검증했다.
- 따라서 "유사 서비스의 폐업/회고 사례" 중 상당수는 **미확인**으로 표기했다. 미확인 항목은 기억에 근거한 가설이며, 후속 세션에서 반드시 검색으로 재확인해야 한다. 출처가 붙은 항목만 "확인됨"이다.

## 3. 실패 원인 상세

### F1. AI 시안과 실물 리폼 결과의 차이 → 불만·환불·분쟁
**메커니즘**
- 생성 모델은 "예쁜 그림"을 만들지 "봉제 가능한 설계도"를 만들지 않는다. 존재하지 않는 소재, 봉제선 없는 패치, 완벽한 그라데이션 염색, 옷의 두께·신축성을 무시한 실루엣 변경이 흔히 나온다.
- 고객은 시안을 "약속"으로 받아들인다. 실물이 다르면 "표시·광고와 다르다"는 하자 주장으로 이어진다. 주문제작 상품이라 단순 변심 청약철회는 제한할 수 있어도(F17), 광고와 다른 결과는 책임을 피하기 어렵다.
- 특히 위험한 디자인 유형: 염색/탈색(결과 예측 불가), 실루엣 변경(핏), 전사·프린트(소재별 발색 차이), 자수(밀도·굵기).

**조기 경고 신호**
- 베타 시 "시안 대비 실물 만족도" 5점 척도 평균 < 4.0
- 재작업 요청률 > 10%, 환불 요청률 > 5%
- CS 티켓 키워드 "사진이랑 달라요/색이 달라요/크기가 달라요"
- 리뷰 사진의 실물과 시안을 나란히 놓았을 때 내부 인원도 차이를 즉시 인지

**기획 단계 검증(가설·실험·질문)**
- 가설: "현재 보유 디자인 중 80% 이상은 사진 한 장 기준 시안과 실물의 차이가 고객 허용 범위 안에 있다."
- 실험: 디자인 5개 × 옷 3벌 = 15건. 디자이너가 Photoshop으로 시안을 만들고(AI 없어도 됨), 장인이 실제 리폼. 제3자 10명에게 시안/실물 쌍을 보여주고 "기대와 같다/다르다/더 좋다" 투표. 다르다 > 30%인 디자인은 템플릿에서 제외하거나 "결과 상이 가능" 등급으로 분류.
- 질문: 디자인별로 "실물에서 재현이 보장되는 변수"(패치 위치·크기, 자수 색)와 "보장 못 하는 변수"(염색 톤, 핏)를 클라이언트 장인이 직접 구분할 수 있는가?

**완화책**
- 템플릿을 "재현 가능 요소"로 한정: 패치/와펜/자수/스티치/트리밍/부자재 교체처럼 결과가 결정적인 요소를 1차 카탈로그로. 염색·실루엣 변경은 2차(면담 필수).
- 시안 UI에 상시 문구: "AI가 만든 예상 이미지입니다. 실제 작업물과 색·질감·위치가 다를 수 있습니다." + 워터마크.
- 주문 후 24시간 내 **장인 확정 시안**(실제 작업 범위 표시: 치수·위치·색상 코드) 발송 → 고객 승인 후 작업 시작. 승인된 확정 시안이 분쟁 기준.
- 작업 중 사진 1회 공유(패치 가봉 상태 등) → 중간 승인.
- 재작업/환불 정책을 "확정 시안 대비"로 명문화.

### F2. "내 옷"에 디자인이 안 어울리는 경우가 많아 추천 품질이 낮음
**메커니즘**
- 디자인은 원래 특정 옷(예: 데님 재킷)을 염두에 두고 만들어졌는데, 서비스는 "아무 옷"을 받는다. 니트에 가죽 패치, 얇은 셔츠에 무거운 자수처럼 물리적으로 부적합한 조합이 다수.
- 디자인 수가 적으면(F12) 추천이 아니라 "전부 보여주기"가 되고, 사용자는 "어울리는 게 없다"고 느낀다.

**조기 경고 신호**
- 시안 생성 후 디자인 선택률 < 20%, 세션당 생성 수는 많은데 주문 전환은 낮음
- 주문의 80%가 상위 3개 디자인에 집중
- 특정 의류 카테고리(코트·니트)에서 주문 0

**검증**
- 디자인 × 의류 카테고리(상의/하의/아우터/소재/두께) 호환 매트릭스를 디자이너·장인이 수작업으로 작성. "가능/조건부/불가" 3단계.
- 20명에게 자기 옷 사진 1장 + 디자인 카탈로그를 주고 "하고 싶은 것"을 고르게 하는 카드소팅. 아무것도 안 고른 비율이 핵심 지표.

**완화책**
- 1차 추천은 룰 기반(카테고리·소재·색 대비)으로, 모델은 "어울림 점수"를 보조로만 사용.
- 촬영 전 "옷 종류 선택"으로 불가 조합을 사전 차단하고, "이 옷에는 N개 디자인이 가능합니다"를 솔직하게 노출.
- 디자인 등록 시 호환 메타데이터(허용 소재·위치·최소 면적)를 필수 입력.

### F3. 생성 품질이 들쭉날쭉해 신뢰 하락
**메커니즘**
- 확률적 생성: 같은 입력에도 결과가 다르다. 원형 보존 실패(색이 미묘하게 바뀜, 핏이 바뀜, 단추 수가 바뀜, 기존 로고가 뭉개짐), 배경·손 왜곡, 디자인이 너무 작게/크게 들어감.
- 호스팅 모델(Gemini/OpenAI 계열)은 전체 이미지를 재생성하는 경향이 있어 "원형 그대로"가 구조적으로 보장되지 않는다. 마스크 기반 인페인팅(예: FLUX Fill 계열)이 원형 보존에는 유리하나, 오픈 가중치는 라이선스 문제(F8)가 있다.

**조기 경고 신호**
- "다시 생성" 클릭률 > 50%
- 내부 QC(원형 보존·디자인 충실·사실성) 합격률 < 70%
- 사용자 체류 후 이탈 지점이 "시안 화면"

**검증**
- 벤치마크 세트 100장: 의류 10종 × 촬영 조건(밝기·배경·입음/펼침) × 디자인 3종. 후보 파이프라인 3종(호스팅 모델 2종 + 마스크 인페인팅 1종)으로 동일 조건 생성 → 디자이너 3인 블라인드 채점. 합격률·재현성(동일 입력 5회 생성 시 편차)·소요 시간·장당 비용 기록.
- 성공 기준 예시: 합격률 ≥ 75%, 원형(비편집 영역) 변화 없음 ≥ 95%, p95 응답 < 20초.

**완화책**
- "편집 영역만 생성 → 원본 위에 합성" 구조로 원형 보존을 **설계로 보장**(모델 신뢰에 맡기지 않음).
- 자동 QC: 비마스크 영역의 원본 대비 픽셀/구조 유사도 검사, 실패 시 재생성 또는 수동 폴백.
- N개 생성 후 자동 점수로 상위 2개만 노출.
- 실패 시 "디자이너가 24시간 내 시안을 보내드립니다"로 전환(플랜 B).

### F4. 리폼 단가 대비 수요 부족(새 옷 사는 게 더 쌈)
**메커니즘**
- 리폼 비용(수만 원) + 왕복 배송 + 1~3주 대기 vs SPA 브랜드 신상 2~5만 원(일반 시세, 미검증). 합리적 소비자는 리폼을 안 한다.
- 리폼이 성립하는 조건은 "이 옷이 아니면 안 되는 이유"(애착·희소·사이즈·추억)뿐이며, 그 모수는 작다.

**조기 경고 신호**
- 랜딩 → 촬영 전환 < 5%, 시안 → 주문 전환 < 3%
- 가격 노출 직후 이탈 급증
- SNS 반응(좋아요·저장)은 높은데 DM/주문은 없음("구경용 서비스")

**검증**
- Before/After 게시물에 **가격을 명시**하고 대기리스트/선주문(소액 예약금) 전환을 측정. 가격 없는 반응은 수요 증거가 아니다.
- Van Westendorp 가격 민감도 설문(30~50명).
- 리폼 경험자 인터뷰 10명: 마지막으로 리폼한 옷은 무엇이고 왜였는가.

**완화책**
- 타깃을 "옷"이 아니라 "이유"로 정의: 추억 의류, 빈티지·브랜드 아이템, 단체복/동아리/굿즈 리폼(B2B·소규모 단체), 아이 옷 리폼.
- 입문 가격대 메뉴(예: 자수 1포인트) + 배송비 포함 표시로 심리적 저항 완화.
- "세상에 하나뿐"을 앵커로, 새 옷 가격과 비교되지 않는 프레이밍.

### F5. 브랜드 상표권 문제
**메커니즘**
- 타 브랜드 로고가 있는 옷을 상업적으로 리폼·광고하면 상표권 침해 주장을 받을 수 있다. 한국에서 명품 가방 리폼업자가 상표권 침해로 패소한 사례(1심 2023년, 2심 2024년으로 기억 — **미확인**, 법률 검토 필수)는 "고객 소유물 수선"이라는 항변이 상업적 리폼에서는 통하지 않을 수 있음을 시사한다.
- 해외에서도 맞춤 커스텀·업사이클 업자에 대한 브랜드 소송 사례가 다수 있는 것으로 기억(미확인).
- 추가 위험: 생성 모델 정책이 타인의 지식재산권 침해 콘텐츠를 금지(Google 정책 확인됨). 로고를 생성·변형하도록 하면 API 차단·계정 정지 가능.
- 클라이언트의 자체 디자인이 타 브랜드 모티프를 차용했을 가능성도 점검 대상.

**조기 경고 신호**
- 브랜드 법무 경고장, 인스타그램 게시물 삭제·계정 경고
- 모델 API의 콘텐츠 거부율 증가(로고 포함 이미지)
- 주문 중 브랜드 로고 의류 비중이 높음(= 리스크 노출 큼)

**검증**
- 변호사 자문 1회: (a) 고객 소유 브랜드 의류 리폼의 적법 범위, (b) 리폼 결과물의 마케팅 사용, (c) 로고 제거·가림의 효과.
- 보유 디자인 전수 점검: 타 브랜드 로고·캐릭터·저작물 포함 여부.
- "리폼 편의점" 상표 선등록 여부 확인(F18).

**완화책**
- 접수 정책: 브랜드 로고 변형·복제·강조 작업 금지, 로고 의류는 로고 영역을 보존하거나 가림 옵션 제공.
- 약관: 고객이 소유권·사용권을 보증, 리폼 결과물의 마케팅 사용 동의는 별도 체크, 로고 노출 홍보 금지.
- 시안 생성 시 로고 영역은 마스크에서 제외.

### F6. 물류(왕복 배송) 비용·시간·분실
**메커니즘**
- 왕복 2회 배송 + 포장 + 검수. 고객 체감 리드타임 = 발송 1~2일 + 검수 1일 + 대기/작업 N일 + 반송 1~2일.
- 분실·오염은 금전으로 대체 불가(애착 의류). 택배 표준약관의 배상 한도(운송장 가액 미기재 시 한도 존재 — **미확인**)보다 고객의 심리적 손해가 훨씬 크다. 1건의 분실이 SNS에서 서비스 신뢰를 무너뜨릴 수 있다.

**조기 경고 신호**
- 평균 리드타임 > 14일, p90 > 21일
- CS 중 "언제 와요?" 비중 > 30%
- 분실·파손 1건

**검증**
- 파일럿 20건으로 실제 왕복 비용·일수·포장 손상률 측정.
- 택배사 기업 계약 단가 견적, 가액 신고·보험 가능 여부, 편의점 택배/반값택배 등 저가 채널 활용 가능성(미확인).

**완화책**
- 접수 시 고객 사진 + 입고 시 검수 사진으로 상태 기록(분쟁 기준).
- 가액 신고·보험 기본 적용, 배송비를 가격에 포함해 "추가 비용" 느낌 제거.
- 서비스명과 어울리는 **편의점 접수/수령** 채널 제휴 검토(미확인), 지역 한정 수거 서비스.
- 리드타임을 "주문 시 약속"으로 노출하고, 초과 시 자동 보상(쿠폰).

### F7. 장인 생산능력 병목과 품질 편차
**메커니즘**
- 리폼은 비정형 수작업. 바이럴로 주문이 100건 몰리면 장인 2~3명으로는 몇 주가 밀린다. 외주 장인을 급히 늘리면 품질 편차가 생긴다.
- "AI가 즉시 시안을 보여주는" 프론트의 속도와 "수작업"의 속도 불일치가 구조적 긴장.

**조기 경고 신호**
- 백로그 > 2주 분량, 리드타임 증가 추세
- 장인별 재작업률·평점 편차 > 2배
- 주문 상한을 걸어야 하는 상황 반복

**검증**
- 클라이언트에게 디자인별 표준 작업시간(분)과 월 처리 가능 건수를 **숫자로** 받는다.
- 바이럴 시나리오(하루 50건·100건) 시 백로그 계산을 기획서에 포함.

**완화책**
- 디자인을 "표준 작업서(SOP)"로 문서화(치수·재료·순서·검수 기준) → 외주 확장 시 품질 유지.
- 주문 상한·예약제·"이번 주 접수 마감" UI.
- 난이도별 메뉴·가격·리드타임 차등.
- 외주 장인 네트워크를 사전에 확보하고 샘플 테스트.

### F8. 모델 API 종속·비용·정책 변경
**메커니즘**
- 특정 모델에 프롬프트·파이프라인을 최적화해 두면, 모델 폐기·가격 변경·안전 필터 변경에 취약. **확인된 예**: Google 가격표에 Gemini 2.5 Flash Image가 "deprecated"로 표기되고 2026-10-02 종료 예정으로 안내됨(https://ai.google.dev/gemini-api/docs/pricing). 1년 남짓한 수명 안에 모델 세대가 여러 번 바뀌었다(Nano Banana → 2 → 2.1 → Pro).
- 오픈 가중치 폴백도 공짜가 아니다: FLUX.1 [dev]/Kontext [dev]는 **비상업 라이선스**(확인됨). 프로덕션 사용은 별도 상업 라이선스 필요.
- 정책: Google 금지 정책은 IP 침해·동의 없는 생체정보·사칭 등을 금지(확인됨). 사람이 입은 사진 편집은 안전 필터에 걸릴 가능성.

**조기 경고 신호**
- deprecation 공지, 모델 버전 업데이트 후 회귀 벤치마크 합격률 급락
- 장당 비용 상승 또는 호출 거부율 상승

**검증**
- 벤더 2개 이상으로 동일 벤치마크(F3) 실행, 추상화 계층 설계 검토.
- 오픈모델 사용 시 라이선스·상업 라이선스 견적 확인.

**완화책**
- 모델 추상화 계층 + 프롬프트/파라미터를 코드와 분리.
- 회귀 벤치마크 자동화(모델 교체 시 1시간 내 품질 확인).
- 폴백 모델 1개 상시 유지, 비용 상한 알림.
- 입력 가이드: 옷만 펼쳐 촬영(사람 없음) 권장 → 안전 필터·개인정보 리스크 동시 완화.

### F9. 데이터 부족으로 "학습" 불가
**메커니즘**
- 파인튜닝(LoRA 등)이 의미 있으려면 디자인당 일관된 before/after 쌍이 수십 장 이상, 전체적으로 수백~수천 장이 필요(일반 경험칙, 미검증). 클라이언트가 가진 것은 대개 "완성품 사진 몇 장"이고 before 사진은 없다.
- 적은 데이터로 학습하면 과적합·일반화 실패 → "학습했는데도 못 함"이라는 최악의 결과.

**조기 경고 신호**
- 데이터 인벤토리 결과 디자인당 쌍 < 20, before 사진 비율 < 50%
- 사진 해상도·조명 일관성 낮음

**검증**
- 데이터 인벤토리 표(디자인 수, 쌍 유무, 해상도, 촬영 조건, 저작권·초상권 상태).
- 1개 디자인 20쌍으로 소규모 LoRA 실험 → 새 옷 5벌에 적용해 합격률 측정. 효과 없으면 "학습" 전략 철회.

**완화책**
- 학습 대신 **레퍼런스 이미지 + 템플릿 자산(패치 PNG, 자수 벡터, 색상 코드) + 마스크** 방식으로 시작.
- 운영하면서 자동 축적: 주문 건마다 입고 사진·완성 사진을 표준 조건으로 촬영 → 6~12개월 후 학습 데이터 확보.

### F10. 촬영 품질 편차
**메커니즘**
- 어두운 방, 구겨진 옷, 바닥 무늬 배경, 입은 상태/펼친 상태 혼재, 일부만 찍힘 → 인식 실패·마스크 오류·시안 품질 저하. "AI가 이상하다"는 인상의 상당 부분이 입력 문제.

**조기 경고 신호**
- 인식 실패·재촬영 요청률 > 15%
- 품질 불만이 특정 촬영 조건(야간·실내)에 집중

**검증**
- 10명에게 아무 안내 없이 촬영시켜 분포(밝기·배경·구도) 확인.
- 촬영 가이드 유무 A/B로 합격률 차이 측정.

**완화책**
- 촬영 가이드 오버레이(실루엣, 밝기 경고, 흔들림 감지), 자동 품질검사 후 재촬영 요청.
- 배경 제거·정규화 전처리, "옷을 펼쳐서 평평한 곳에" 단일 포맷으로 통일.

### F11. 클라이언트의 "학습" 기대와 실제 가능 범위의 괴리
**메커니즘**
- "우리 디자인을 학습시키면 어떤 옷이든 자동으로 적용된다"는 기대는 (a) 데이터(F9), (b) 호스팅 모델의 이미지 파인튜닝 가능 여부(2026년 기준 미확인), (c) 원형 보존의 구조적 한계(F3) 때문에 그대로 실현되기 어렵다. 실제로 가능한 것은 "레퍼런스 주입 + 마스크 편집 + 룰 기반 템플릿"이며, 이것도 QC가 필요하다.
- 기대 불일치는 일정·예산·검수 책임 분쟁으로 번진다.

**조기 경고 신호**
- 회의에서 "학습시키면 되죠?"가 반복, 요구사항에 "모든 옷", "자동", "100%" 표현
- 성공 기준이 숫자로 합의되지 않음

**검증**
- 기대치 정렬 워크숍: 현재 공개 모델로 클라이언트 옷 3벌을 **그 자리에서** 생성해 보여주고, 가능/불가능을 눈으로 확인.
- 성공 기준 수치 합의(합격률, p95 응답시간, 리드타임, 재작업률).

**완화책**
- "학습"을 3단계로 정의해 계약에 명시: L1 레퍼런스/프롬프트/템플릿(즉시 가능) → L2 LoRA 소규모(데이터 조건부) → L3 전용 모델(장기·고비용). 각 단계의 데이터 요건·비용·기대 품질을 표로.
- 단계별 Go/No-Go 게이트와 중단 조건.

### F12. 디자인 수가 적어 선택지가 빈약함
**메커니즘**
- "편의점"이라는 이름은 다양성·즉시성을 약속한다. 디자인 10개 미만이면 약속 위반이고 재방문 이유가 없다.

**조기 경고 신호**
- 디자인 목록 화면 이탈률 높음, "다른 거 없어요?" 문의
- 재방문율 < 10%

**검증**
- 보유 디자인 수·유형·확장 계획 확인(질문 목록).
- 파라메트릭 변형(색·위치·크기) 적용 시 사용자가 "다른 디자인"으로 느끼는지 테스트.

**완화책**
- 템플릿을 파라메트릭(색/위치/크기/조합)으로 설계해 체감 선택지 확대.
- 시즌 한정·협업 디자인, 고객 요청 투표.

### F13. 기획이 길어지고 PoC 없이 확신 못 함
**메커니즘**
- "실제로 되는지"는 문서로 답할 수 없다. 검증 없는 기획은 길어질수록 확신이 줄고, 그 사이 모델·시장이 바뀐다(F8).

**조기 경고 신호**
- 기획 리뷰 3회 이상 후에도 기술 가능 여부 미결론
- 의사결정 날짜가 계속 밀림

**검증/완화**
- 기획 단계 안에 타임박스 검증을 내장: 2주 기술 PoC(F3 벤치마크) + 2주 수요 테스트(F4 Wizard-of-Oz). 결과로 Go/No-Go.
- 게이트 날짜를 고정하고, 게이트 통과 기준을 사전에 숫자로.

### F14. 개인정보·초상권·안전 필터(추가)
- 사용자가 옷을 "입고" 찍으면 얼굴·신체·배경(집)이 포함된다. 개인정보 처리·보관·삭제 정책이 필요하고, 모델 정책(동의 없는 생체정보 금지 — Google 정책 확인됨)에 걸릴 수 있다.
- 완화: 얼굴 자동 블러/크롭, 옷만 촬영 유도, 원본 보관 기간 최소화, 마케팅 사용은 별도 동의.

### F15. 단위 경제 붕괴(추가)
- AI 생성 비용 자체는 작다(장당 수십 원~수백 원 수준: Google $0.03~$0.13/장 확인됨). 문제는 **사람 비용**: 디자이너 QC(건당 10~30분), 장인 작업, 왕복 배송, CS. 객단가 3~5만 원에서 공헌이익이 마이너스가 되기 쉽다.
- 검증: 건당 원가표(AI/QC/장인/배송/포장/CS/결제수수료) 작성 후 파일럿 실측.
- 완화: 난이도별 가격, 자동 QC로 사람 개입 축소, 최소 주문 금액.

### F16. 획득비용 > 객단가(추가)
- 바이럴은 1회성. 재구매가 드문 카테고리라 CAC 회수가 어렵다.
- 완화: B2B(단체복·굿즈·브랜드 리페어 서비스 — SOJO가 B2B로 무게중심을 옮긴 사례 확인됨), 시즌 디자인으로 재구매 동기.

### F17. 주문제작 환불 규정 미비(추가)
- 주문제작 상품은 전자상거래법상 사전 고지와 동의 요건을 갖추면 청약철회를 제한할 수 있는 것으로 알려져 있으나 조문·요건은 이 세션에서 **미확인**. 요건을 못 갖추면 "AI 시안 보고 주문했는데 마음 바뀜" 환불을 거절할 근거가 없다.
- 완화: 주문 직전 고지·동의 체크 UI, 확정 시안 승인 단계(F1), 분쟁 해결 기준 문서화, 법률 검토.

### F18. "리폼 편의점" 상표·도메인(추가)
- 서비스명 자체의 상표 선등록·유사 상표 여부를 이 세션에서 확인하지 못했다(KIPRIS 검색 필요). 출시 후 이름을 바꾸면 SNS 자산을 잃는다.
- 완화: 기획 초기에 상표 조사·출원, 대체 네이밍 2개 확보.

## 5. 기획 단계에서 꼭 답해야 할 질문 (클라이언트 확인 사항)

3. 디자인별로 적용 가능한 의류 종류·소재·위치 제약을 문서로 가지고 있는가? 없다면 장인이 작성할 수 있는가?
4. 디자인에 타 브랜드 로고·캐릭터·저작물이 포함된 것이 있는가?
5. 디자인을 파라미터화(색/위치/크기 옵션)할 의향이 있는가?

12. 주문이 하루 50건 몰리면 어떻게 할 것인가?

### 5.4 가격·수익

15. 배송비는 고객 부담인가 포함인가?

### 5.5 타깃·고객 데이터
16. 기존 고객은 누구인가(연령·성별·채널)? 재구매율은?
17. 기존 주문·문의·리뷰 데이터(사진 포함)가 있는가? 사용 동의는 받았는가?
18. 고객이 리폼을 맡기는 "이유" Top 3는?

### 5.6 브랜드 의류·법무
19. 타 브랜드 로고 의류를 취급하는가? 로고를 변형한 적이 있는가? 경고를 받은 적이 있는가?
20. 리폼 결과물을 SNS 마케팅에 쓰고 있는가? 고객 동의 절차는?
21. "리폼 편의점" 상표 출원 여부·도메인 확보 여부는?

### 5.7 예산·일정·기대
22. 총 예산 범위와 운영(모델 API·인프라·QC 인력) 월 예산은?

24. "학습"에 기대하는 결과를 한 문장으로 쓰면? 자동화 100%가 아니어도 되는가?
25. 성공 기준을 숫자로 합의할 수 있는가(합격률·리드타임·전환율)?

### 5.8 물류·운영

## 6. 핵심 가설과 최저비용 검증

| 구분 | 가설 | 최저비용 검증 방법 | 성공 기준(초안) | 비용·기간 |
|---|---|---|---|---|
| 가치 V1 | 사람들은 "내 옷에 적용된 시안"을 보면 리폼 의향이 생긴다 | 인스타/틱톡에 Before/After(AI 또는 포토샵) 10개 게시, 저장·DM·대기리스트 전환 측정 | 게시물당 DM/대기리스트 ≥ 20건, 가격 공개 후에도 유지 | 디자이너 3일, 광고비 0~30만 원, 2주 |
| 가치 V2 | 가격을 알아도 주문한다 | 대기리스트에 가격·리드타임 명시 후 소액 예약금(1만 원) 선주문 | 대기리스트 → 선주문 ≥ 10% | 2주 |
| 가치 V3 | 시안과 실물의 차이를 고객이 수용한다 | Wizard-of-Oz: 포토샵 시안 → 실제 리폼 15건 → 만족도 조사 | 만족도 ≥ 4.0/5, 재작업 ≤ 10% | 장인 시간, 3~4주 |
| 기술 T1 | 사진 1장으로 원형 보존 시안을 자동 생성할 수 있다 | 100장 벤치마크로 모델 3종 블라인드 채점(F3) | 합격률 ≥ 75%, 비편집 영역 변화 없음 ≥ 95% | API 비용 수만 원, 2주 |
| 기술 T2 | 디자인을 "학습" 없이 레퍼런스+템플릿으로 일관되게 적용할 수 있다 | 디자인 3개 × 옷 10벌, 레퍼런스 주입 방식으로 생성 → 일관성 채점 | 디자인 식별 가능률 ≥ 90% | 1주 |
| 기술 T3 | 소규모 파인튜닝이 레퍼런스 방식보다 낫다 | 1개 디자인 20쌍 LoRA vs 레퍼런스 방식 A/B | 합격률 +15%p 이상일 때만 채택 | 2주, GPU 비용 소액 |
| 기술 T4 | 일반 사용자의 촬영으로도 인식·마스크가 된다 | 10명 자유 촬영 + 가이드 촬영 비교 | 가이드 있을 때 성공률 ≥ 85% | 1주 |
| 수익 R1 | 건당 공헌이익이 양수다 | 원가표 + 파일럿 15건 실측 | 공헌이익 ≥ 객단가의 25% | 파일럿과 병행 |
| 수익 R2 | 재구매 또는 B2B로 CAC를 회수한다 | 파일럿 고객 3개월 후 재구매 의향·추천 측정, 단체복/굿즈 수요 인터뷰 5건 | 재구매 의향 ≥ 30% 또는 B2B 리드 ≥ 3 | 3개월 |
| 운영 O1 | 리드타임 14일 이내를 지킬 수 있다 | 파일럿 20건 물류·작업 실측 | p90 ≤ 14일 | 파일럿과 병행 |
| 법무 L1 | 브랜드 로고 의류 정책으로 법적 리스크를 관리할 수 있다 | 변호사 자문 1회 + 정책 초안 | 자문 의견서 확보 | 1~2주 |

권장 순서: V1 → T1(병행) → V2 → V3/O1/R1(파일럿 묶음) → T2/T3 → L1. V1과 T1이 모두 실패하면 중단을 검토한다.

## 7. 플랜 B: 대안 스코프

| 단계 | 스코프 | 사용자 경험 | 원형 보존 | 즉시성 | 비용 | 언제 선택 |
|---|---|---|---|---|---|---|
| A (목표) | 완전 자동: 촬영 → 인식 → 추천 → 생성 즉시 | 수십 초 내 시안 | 모델 의존(설계로 보완) | 높음 | API+QC | T1 합격률 ≥ 75% |
| B1 반자동 | AI가 인식·마스크, **디자이너가 템플릿 위치·크기만 조정** 후 생성 | "시안 준비 중" 알림, 수 분~2시간 | 높음 | 중 | 디자이너 건당 5~10분 | T1 50~75% |
| B2 수동 시안 | 디자이너가 포토샵 템플릿(스마트 오브젝트)로 시안, **24시간 내 회신** | 다음 날 시안 | 매우 높음 | 낮음 | 디자이너 건당 15~30분 | T1 < 50% 또는 PoC 전 수요 테스트 |
| B3 오버레이 미리보기 | 생성 없이 패치/자수 PNG를 옷 사진 위에 드래그·크기 조절(스티커 방식) | 즉시, 사용자가 직접 배치 | 100% | 매우 높음 | 거의 0 | 비용 최소화·즉시성 필요 시 |
| B4 카탈로그 | 유사 옷의 기존 Before/After 사례를 보여주고 주문 | 즉시 | 해당 없음 | 높음 | 0 | 디자인 데이터는 있으나 생성이 불안정할 때 |

**권장 하이브리드**: B3(즉시, 100% 원형 보존, 기대치 관리에 유리) + 주문 후 B1(고품질 확정 시안, 장인 검토 포함). 완전 자동(A)은 T1이 기준을 넘는 디자인 유형(패치·자수 등 결정적 작업)부터 단계적으로 켠다. 이렇게 하면 F1·F3·F8·F15 리스크를 동시에 줄인다.
